## 3D 场景

路径：**应用设置 → 模型测试实验室 → 3D 空间模拟实验室**。

- 坐标系：右手系，+X 右、+Y 上、+Z 前；米、角度制。Yaw=0 正前（+Z），Yaw=90 朝 +X；Pitch 正向上。
- 玩家位置与朝向、摄像机相对位置/朝向/FOV、准心二维规范坐标、射线起点/方向/交点。
- 头、躯干、左右手臂、左右腿的局部坐标、世界坐标、前向量。
- 物品/地块采用轴向包围盒，可显示相机/玩家到物体距离、朝向角与射线命中。
- 以固定秒数模拟移动/转向；可编辑场景 JSON，输出可直接发给模型的模型观察 JSON。操作不连接真实游戏，也不会自动读取玩家数据。
- 核心模块：`app/src/main/assets/labs/spatial-core.js`，可在 Node 下不依赖浏览器进行回归：`node scripts/test-spatial-lab.cjs`。
- 离线独立 WebView 禁用 Android JavascriptInterface，JS 没有文件/网络权限调用桥。当前实现不是物理引擎：无动画骨骼、重力、导航网格、物理碰撞响应或真实游戏 API。
- 视窗渲染按固定 960×600 的投影进行；JSON 中的准心射线目前采用固定 16:9 横纵比，属于 V1 已知限制（后续需通过 viewport 统一）。

## 真正的 Luau CLI

入口：**应用设置 → 模型测试实验室 → Luau 代码测试**。

`LuauTestRunner.kt` 只调用应用私有运行时 `usr/bin/luau`，不以 Lua 5.x 或 WebView JavaScript 替代。当前仓库默认快照并未保证包含此二进制；未找到时明确报错，绝不标记测试成功。

集成计划：
1. 在 Android/Termux 对应架构的构建环境从 [Luau 官方源码](https://github.com/luau-lang/luau) 构建 `luau` CLI，验证与设备 ABI/NDK/Termux libc 兼容。
2. 将可执行文件及其动态依赖加入构建脚本的暂存快照（`stage/usr/bin/luau`），加入 smoke：`luau --version` 并运行独立测试脚本。构建过程应当固定源码版本/校验值，不能拉取未经确认的可执行文件。
3. 在设备上进行 LuaU 语法、型别检查与实际运行验证。注意 Roblox 服务（Workspace、Players、Instance 等）不属于独立 CLI，需额外模拟 API；当前不提供。
4. 后续接入模型辅助生成/理解场景可使用上述统一观察 JSON，不自动执行未经用户确认的游戏脚本。

**安全约束**：当前 Luau CLI 入口只适用于可信测试脚本；超时与输出大小限制不是进程沙箱，不可对任意不可信代码声称安全。执行前需额外增加隔离/资源配额才能开放任意来源的脚本。

## 3D 第二版（V2）

V2 入口取代 V1 页面，V1 核心 `spatial-core.js` 继续保留供旧项目测试及迁移。

- **空间对象：** 物品及地块具备三轴旋转、带旋转包围盒和射线交点法线。角色各部位具有局部坐标、世界坐标、朝向和圆球碰撞近似。
- **空间观测：** 使用场景声明的实际视口比例；返回物体屏幕投影（像素和 NDC）、前后左右相对方位、地块所在关系、表面距离、遮挡标志和遮挡者。准心排除玩家自身各部位，避免第三人称相机射线误判。
- **相机：** 跟随与自由模式、摄像机独立移动/旋转、基于目标自动瞄准。
- **运动：** 可重复的离散步进、路径采样和可能重叠提示。重叠提示**不是**真实碰撞求解/导航。几何能见度检查当前按物体中心点，最多采样 48 个屏幕内物体，多余对象明确标为 `not_tested`，避免将未检测误报为可见。
- **数据兼容：** `DshSpatialV2.normalize()` 接受 V1，自动升级视口、角度和默认旋转，采用 `dsh-spatial-v2` 与 `dsh-spatial-observation-v2` 版本标识。
- **验收：** `node scripts/test-spatial-v2.cjs` 测试旋转包围盒、投影/屏幕射线反算、遮挡、移动、V1 迁移和 2,000 次确定性随机观测。
- **限制：** 当前视线能见度为中心点探测；非物理引擎，不含实体动画/碰撞响应；V2 的相机 roll 已包含旋转基，但投影和屏幕射线仅支持 yaw/pitch，roll 非零时当前尚不用于画面投影（后续修正前应设置 roll=0）。

## 3D V3 迭代（独立离线模拟）

- 场景 Schema `dsh-spatial-v3`、输出 `dsh-spatial-observation-v3`，自动接收 V1/V2 数据，V1/V2 核心保留用于回归。
- 修复**相机 Roll 的屏幕投影与准心反投影**；玩家位置、摄像机姿态、准心射线使用相同视口。
- 物体可见性从中心点扩展至 **中心及 6 个面中心采样**，输出可见/部分可见/被遮挡/视野外/未测试，以及样本数；检测上限为最近的 24 个视野候选，以限制 CPU 消耗。
- 玩家碰撞以高度抽样的**保守扫掠球近似胶囊体**，支持旋转包围盒、阻挡与滑动；报告碰撞点、表面法线和碰撞对象。无法替代精确的物理引擎、动态刚体/多角色碰撞或复杂初始穿插求解。
- 运动历史记录最长 60 帧；模型可读取轨迹、碰撞事件、相机方向、投影及可见性证据。
- 新增独立 V3 HTML 场景面板、碰撞/遮挡预设、自由相机 Roll 和运动操作、场景导入以及 JSON 导出。应用设置使用 V3 页面，V2 保留作为兼容参考。
- 回归测试：`node scripts/test-spatial-v3.cjs`，覆盖 V1/V2 迁移、Roll 逆投影、墙体阻挡、滑动、遮挡、历史上限、1500 个确定性随机场景。
- 本实验室不连接真实游戏，也不访问数据库 PR #28。

## 3D V4：动态场景、空间变化与导航

- V4 Scene: `dsh-spatial-v4`；Observation: `dsh-spatial-observation-v4`；继承 V1–V3 场景并迁移，V1/V2/V3 核心文件保留。
- `agents` 动态实体清单：ID、角色（ally / neutral / opponent / target）、位置、速度、Yaw、碰撞半径。常速度步进属于模拟预测，**非 NPC AI 或真实游戏数据**。
- `deltaReport`：对比动作前后玩家、相机和动态实体位置变化及准心目标变化，并保留碰撞事件摘要。单次最多输出 96 条事件。
- `replay`：用户输入动作数组的确定性回放，单次最多 64 步；`modelPacket`：按距离排序、限量的模型摘要，包含空间关系、视野证据、来源和限制。
- `planPath`：限定 48 米目标范围、5000 扩展节点上限的 XZ 网格 A*。考虑静态旋转包围盒和模拟实体占位，拒绝斜向穿角，对路径进行采样平滑。状态包括 `found`、`already_there`、`target_blocked`、`goal_cell_blocked`、`budget_exhausted`、`no_path`。预算不足和找不到路径不等价。
- 交互：V4 页面包含玩家移动、目标坐标寻路、模型简报、5 步回放、场景编辑与观察导出。
- 验证：`node scripts/test-spatial-v4.cjs` 覆盖导航、动态实体、回放、边界、历史、600 个确定性场景。
- 限制：仍为离线几何模拟；寻路没有坡度、重力、真实移动控制、物理导航网格与在线世界感知。原始数据库项目继续暂停。


## V4 审计整改（Issue #30）

- 寻路：A* 邻接边和路径平滑线段都使用碰撞通行验证，返回 `found` 前逐段检查；避免细墙穿透与重复终点。
- 命中：动态角色球体与静态旋转盒统一最近射线命中，准心结果包含 `agent` 类型。
- 动态实体：对静态实体盒进行扫掠球碰撞检测并滑动，输出 `agent_collision`。**不声称实现动态角色之间的完整物理碰撞**。
- 增量：新增角色/镜头朝向、准心、物品变化、速度变化等事件。
- 性能：`planPathAsync` 支持协作式分批执行、UI 取消与进度反馈，保留同步纯函数供测试；不是独立线程。
- 安全：空间 WebView 禁止网络加载和跨文件访问；Luau CLI 仅供可信脚本，输出限制为 16 KiB，不生成无限日志，但仍非安全沙箱。
- 测试：`scripts/test-spatial-audit.cjs` 将 Issue #30 的反例纳入 CI。Android APK/实机仍需另行验收，暂不合并 PR。
