# DSH 原生数据库 — 三轮交付与安全契约

## 范围

本分支从 `fix/startup-plugin-recovery-20261013` 衍生，先实现宿主级持久化存储，不修改 DSH 官方 Agent 核心。实现顺序：

1. **第 1 轮：存储与权限基础。** Android SQLite 分区、文本条目、文件私有存储和特殊类型的凭据引用，默认长期记忆分区、权限范围模型、写操作授权检查、DDL 回归测试。
2. **第 2 轮：安卓设置与数据库界面。** 工具页“数据库”入口、数据库列表与详情、分区创建/编辑/删除、文本与文件操作、权限和重要性、总开关、格式化两次确认以及第二次确认前至少 5 秒等待。
3. **第 3 轮：模型访问与特殊功能。** MCP/Host 安全访问接口、会话与工作区授权验证、Keystore 凭据代理、模型写入请求的用户确认、危险操作审计、备份/迁移/异常恢复及 Android 实机回归。

## 数据模型

- `partitions`: id、标题、描述、重要性、访问模式与身份、模型读取许可、写入确认策略、默认分区标记、创建及更新时间。
- `entries`: 关联分区、文本/文件/特殊三种类型、标题、文本正文或外部引用、描述与时间戳。
- 默认仅有 `long_term_memory`，标题为 **长期记忆**，重要性高，**模型读取默认关闭**，模型写入必须取得用户授权。
- 数据分区 `access_mode`: `global` / `conversation` / `workspace`。指定范围时必须有具体的会话或工作区 ID。
- 数据重要性: `low` / `normal` / `high` / `critical`。此属性将用于模型检索排序提示，而**不能替代访问控制**。
- 访问模式和分区描述将指导模型选择读取分区，但**工具/宿主必须再次实施访问检查**，不可相信模型自己执行过滤。

## 存储与凭据安全

- `DshDatabaseStore` 为 SQLite 的唯一宿主入口；用户数据不与 Termux profile 混存在一个自由读写路径。
- `DshDatabaseAttachments` 只接受由宿主创建的随机附件 ID，限制 32 MiB、文件名校验、私有目录存储。
- 特殊类型 **不得保存明文 GitHub Token、密码或 SSH 私钥**。第一轮只允许 `keystore:` 引用；真正的 Keystore 加密和外部服务操作必须等第 3 轮实现、测试后才能开放。
- 数据库文件并非加密数据库。第一轮**不承诺静态加密、凭据保管或特殊连接已可用**。
- 无授权的模型不能看到长期记忆：新建分区默认模型读取关闭。即使打开读取权限，指定会话或工作区也仍需要相应上下文匹配。
- 重要操作的授权应由原生 UI 发起并传递给数据层。不可接受模型在工具参数中自行写入 `approved:true` 作为真实授权。
- `formatAll` 是底层原语；5 秒等待和再次确认属于第二轮 UI/控制器门禁。在第二轮完成前 **不得向模型暴露该操作**。

## 本阶段限制与必须跟进的问题

- 文件导入与数据库元信息写入目前是独立步骤；异常时可能留下未引用的附件，需要在第二轮引入原子登记/垃圾回收流程。
- 分区与条目删除没有可视化恢复/回收站；正式开放前必须加确认与必要的备份策略。
- 特殊凭据只有引用类型，尚无 Keystore Broker、设备生物认证和细粒度外部操作授权。
- 模型访问尚未接入 MCP；不能宣称模型已经能按说明自动检索。
- 当前存储 API 是 Android 内部实现，并非对所有第三方插件公开的无约束数据库 API。
- SQLite DDL、外键和 CHECK 约束已纳入 `scripts/test-database-schema.py`；Android 编译与真实设备持久化仍需分别验收。

## 第一轮验证

运行：

```sh
python3 scripts/test-database-schema.py
bash scripts/check-remaining-fixes.sh
```

Android GitHub CI 通过后，进一步运行 `DSH_PREFLIGHT_ONLY=1 bash build-termux.sh`，随后 `bash build-termux.sh`。GitHub Gradle Debug APK 成功不代表在 Termux 的完整构建成功。

## 第 2 轮提交范围（待实机验收）

- Android Tools 页新增「数据 → 数据库」入口，经随机 Capability 校验的 WebView Bridge 打开原生 `DshDatabaseUi`。网页无法传入 SQL、附件路径或数据库指令。
- 原生页面提供「数据库」与「设置」两部分。分区可创建、编辑访问模式/重要性/描述/模型读取权限及删除；条目可创建、编辑、删除文本，按 40 条分页查看；文件通过 Android `OpenDocument` 选择，并用应用私有目录存储。
- 数据库开关保存在应用私有 SharedPreferences，关闭后界面拒绝进入数据库；目前尚未接入模型访问，因此第三轮还需让 MCP 工具严格读取并遵守同一开关。
- 格式化采用两次确认。第二次确认的按钮使用 `elapsedRealtime()` 距离首层确认后至少 5 秒才能点击；存储层重置默认长期记忆的访问许可并清空自定义分区与记录；之后清理无引用的附件。
- 文件引用登记与导入采用“先导入、后登记”；登记失败会尝试清理孤立文件。清理不能被视为跨 SQLite 与文件系统的原子事务。
- 特殊类型仍只允许引用，真实 Keystore 密钥保存与外部服务操作必须延后至第 3 轮。
- Android 原生 UI 尚未在实机进行旋转、低内存恢复、权限失效、文件选择中断等测试。文件较大时导入仍应移出 UI 线程，以消除潜在卡顿；请勿误报已验证完成。
